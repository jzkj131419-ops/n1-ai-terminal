# 广发信用卡差异核查任务：错因模型建立

> 立项：2026-06-01  
> 背景：周贤案广发信用卡数据，源Excel(55776信用卡流水.xlsx) vs 附表(周贤_审计附表.xlsx) 出现双向差异  
> **目标：不是补录，是找出错因模型**

---

## 一、问题描述

```
源Excel实卡有效行:  14,968
附表行数:           14,789
净差:                  179 行

但实际双向差异：
  源有附表无（缺失）: 577 行  ¥189,797.07
  附表有源无（多出）: 398 行  金额待统计
```

**关键问题：** 为什么会同时出现大量"缺失"和"多出"？
正常的解析错误只会产生单向差异（漏读 → 只缺失）。  
双向大量差异说明解析过程发生了**错位配对**或**重复归并**。

| 类型 | 行数 | 金额 | 代表条目 |
|------|------|------|---------|
| 还款（人行跨行清算） | ~6行 | ¥47,000 | 网上支付跨行清算系统还款(人行) |

> 注：前4类是真实漏录（量少但价值高）；最后一类才是真正要找错因的

## 三、待查错因假说

### 假说A：金额四舍五入导致 key 不匹配
- 源Excel金额有小数（如 ¥336.99），解析时四舍五入为整数（¥337）
- 导致 (日期, 金额) 配对失败 → 一行变成"缺失+多出"各一条
- **验证方法**：对缺失577行按日期找附表同日条目，看金额差是否 < ¥1

### 假说B：同日同金额多笔交易数量不匹配
- 源Excel某日有3笔 ¥73（地铁），附表只有2笔
- Counter差值显示缺1行，但实际是数量不对
- **验证方法**：找 (日期, 金额, 数量) 三元组完全一致的，从diff里去掉，看剩多少真缺失

### 假说C：解析器对广发信用卡特殊交易码的处理规则
- 广发源Excel有 `交易代码` 列（如5883=分期利息入账，1006=退货）
- 解析器对"退货"（交易码1006）的处理：是正向还是负向？
- 若退货被当成收入处理但金额符号错，会出现金额配对失败
- **验证方法**：统计缺失577行 vs 多出398行中，退货码(1006)的占比

### 假说D：日期偏移
- 信用卡账单日与交易日不同（如3号消费，15号入账）
- 解析器用了账单日而非交易日，导致 ±1~15天偏移
- **验证方法**：按交易日+1/7/15天重新匹配，看匹配率是否显著上升

## 四、核查清单生成目标（下次执行）

不是生成"漏录核查清单"，而是生成**"差异错因核查清单"**：

```
输出格式：
  A列：日期
  B列：金额
  C列：源描述
  D列：附表最近匹配条（金额相差<5%，日期相差<15天）
  E列：匹配距离（日期差、金额差）
  F列：疑似错因（四舍五入/日期偏移/数量不足/无匹配）
  G列：是否真实漏录（待人工标注）
```

目标：把577行缺失分成：
- **可解释差异**（金额精度/日期偏移/数量配对）→ 不算漏录，修复解析规则
- **真实漏录**（无法解释的差异）→ 才需要补录
